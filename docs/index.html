¿Necesito internet o una API key?Do I need internet or an API key?

Solo internet una vez, para descargar el modelo de embeddings (~130MB) en el primer init. Después todo es offline. Nunca hay API keys ni cuentas.Internet only once, to download the embedding model (~130MB) on the first init. After that everything is offline. No API keys or accounts, ever.

¿Qué pasa si aún no descargué el modelo? ¿Falla la búsqueda?What if I haven't downloaded the model yet? Does search break?

No. La búsqueda degrada con elegancia: sin modelo funciona en modo keyword-only (MiniSearch/BM25) — nunca falla por falta de modelo. Cuando el modelo aparece y el índice no tiene vectores, se fuerza un reindex completo automáticamente (v0.5.1+); no necesitas reindex --force a mano.No. Search degrades gracefully: without the model it runs keyword-only (MiniSearch/BM25) — it never fails for a missing model. When the model becomes available and the index has no vectors, a full reindex is forced automatically (v0.5.1+); no manual reindex --force needed.

¿Por qué los scores de similitud son todos ~0.8?Why are the similarity scores all ~0.8?

El modelo e5-small comprime los cosenos (~0.76–0.86 incluso para temas no relacionados), así que el número crudo no sirve como confianza. Por eso Alexandria muestra una etiqueta ● high/medium/low relevance relativa al mejor resultado — confía en el ranking, no en el número.The e5-small model compresses cosines (~0.76–0.86 even for unrelated topics), so the raw number isn't meaningful as confidence. That's why Alexandria shows a ● high/medium/low relevance label relative to the best hit — trust the ranking, not the number.

El índice derivado vive en <vault>/.vault/ (meta.json + embeddings.bin) y siempre es regenerable con ale reindex. Vault por defecto: ~/Alexandria (global) o ./Alexandria (por proyecto).Notes in <vault>/Alexandria/*.md (markdown with YAML frontmatter + [[wikilinks]], a valid Obsidian vault). ¿Se borra algo alguna vez? ¿Qué hace clean?Is anything ever deleted? What does clean do?

El conocimiento nunca. ale clean solo toca prompts: los de más de 45 días sin reuso se compactan en un archivo por proyecto-mes en archive/ con el texto íntegro (se verifica releyendo antes de borrar cada original); salen del índice vectorial y del grafo, pero siguen buscables con ale search --archive y como respaldo de vault_search. Los "prompts" que en realidad inyectó el arnés (<task-notification>…) se descartan. Lecciones, planes, mapas, verificaciones, notas y sesiones jamás se tocan. En una bóveda real de 3042 notas: índice 17.3 → 10.5 MB, 642/642 notas de conocimiento idénticas byte a byte.Knowledge, never. ale clean only touches prompts: those older than 45 days and never reused are compacted into one file per project-month in archive/ with their full text (verified by re-reading before each original is removed); they leave the vector index and the graph but stay searchable with ale search --archive and as a vault_search fallback. "Prompts" that the harness actually injected (<task-notification>…) are dropped. Lessons, plans, maps, verifications, notes and sessions are never touched. On a real 3042-note vault: index 17.3 → 10.5 MB, 642/642 knowledge notes byte-identical.

¿Cómo ahorra tokens al leer PDFs, Word o Excel?How does it save tokens when reading PDFs, Word or Excel?

Leer un PDF directo le cuesta al agente ~1,500–3,000 tokens por página: Claude manda cada página como imagen + texto (docs de Anthropic). Con doc_ingest Alexandria lo convierte localmente a secciones y devuelve solo el índice (~200 tokens); con doc_read el agente pide las secciones o hace una pregunta, sin pasar de max_tokens. En hojas de cálculo devuelve solo las filas que coinciden. Medido con documentos reales: un manual de 10 páginas pasó de ~20,000 tokens a ~179 para responder una pregunta; una hoja de 2,016 filas, de ~1.24 M a ~579. En Claude Code, la primera lectura directa de un PDF grande se redirige sola (toggle docs.interceptRead).Reading a PDF directly costs an agent ~1,500–3,000 tokens per page: Claude sends each page as image + text (Anthropic docs). With doc_ingest Alexandria converts it locally into sections and returns only the outline (~200 tokens); with doc_read the agent asks for sections or a question, never over max_tokens. For spreadsheets it returns only the matching rows. Measured on real documents: a 10-page manual went from ~20,000 tokens to ~179 to answer one question; a 2,016-row sheet, from ~1.24 M to ~579. In Claude Code the first direct read of a large PDF is redirected automatically (toggle docs.interceptRead).

¿Cómo maneja la ventana de contexto?How does it manage the context window?

Sin reescribir el historial (resumirlo rompe el caché del proveedor y pierde hechos). En su lugar: pliega la salida grande de comandos (tests, builds, logs: errores + resumen + final; el resto en disco), ofrece un mapa de código para pedir un símbolo en vez de leer archivos enteros, no reinyecta notas que ya están en la sesión, guarda una cápsula antes de compactar (objetivo, archivos, comandos, lo guardado) y la reinyecta después, y marca como reemplazado el conocimiento desactualizado para que no se inyecte. Medido: un test suite de 12.1 KB llega como 1.4 KB; src/cli.ts (~13,600 tokens) como outline de ~253.Without rewriting history (summarizing it breaks the provider cache and loses facts). Instead it folds large command output (tests, builds, logs: errors + summary + tail; the rest on disk), offers a code map to ask for one symbol instead of reading whole files, doesn't re-inject notes already in the session, saves a capsule before compaction (goal, files, commands, what was saved) and re-injects it after, and marks outdated knowledge as superseded so it isn't injected. Measured: a 12.1 KB test suite arrives as 1.4 KB; src/cli.ts (~13,600 tokens) as a ~253-token outline.

¿En qué se diferencia de caveman o Context Mode?How is it different from caveman or Context Mode?

Son complementarios. caveman comprime lo que el modelo lee y dice (y enruta a modelos más baratos); Context Mode es un proxy que "dobla" la salida de herramientas antes de mandarla al modelo. Ambos recortan el tráfico de esta sesión. Alexandria recuerda entre sesiones: no re-derivas lo que ya resolviste, todo local, sin proxy, sin cuenta y sin que tus prompts salgan de tu máquina. Puedes usarlos juntos.They are complementary. caveman compresses what the model reads and writes (and routes to cheaper models); Context Mode is a proxy that folds tool output before it reaches the model. Both trim the traffic of this session. Alexandria remembers across sessions: you don't re-derive what you already solved — fully local, no proxy, no account, your prompts never leave your machine. Use them together.

A veces no me inyectaba el contexto aunque estuviera instalado — ¿por qué?Sometimes it didn't inject context even though it was installed — why?

Era un bug real, corregido en v1.2.0. Si la bóveda se quedaba sin vectores (índice degradado), el hook de cada prompt intentaba reconstruir el índice entero dentro de su presupuesto. En una bóveda de ~1100 notas eso tarda 73 segundos medidos, pero el hook corta mucho antes: cada intento moría a mitad y volvía a guardar el índice sin vectores, así que el siguiente prompt repetía todo — y fallaba en silencio. Ahora los hooks nunca construyen el índice (solo lo consultan, ~550 ms), la reconstrucción ocurre en ale reindex o en segundo plano al cerrar sesión, y los errores quedan registrados en ~/.cache/alexandria/hook-errors.log. Si vienes de una versión anterior, corre ale doctor: detecta el índice degradado y lo repara.It was a real bug, fixed in v1.2.0. If the vault lost its vectors (degraded index), the per-prompt hook tried to rebuild the whole index within its budget. On a ~1100-note vault that takes 73 seconds measured, but the hook cuts off far sooner: every attempt died halfway and saved the index without vectors again, so the next prompt repeated everything — failing silently. Now hooks never build the index (they only query it, ~550 ms), rebuilding happens in ale reindex or in the background at session close, and errors are logged to ~/.cache/alexandria/hook-errors.log. Coming from an older version? Run ale doctor: it detects the degraded index and repairs it.

¿Cómo me ayuda Alexandria a planear mejor?How does Alexandria help me plan better?

plan_create (v1.0.0+) actúa como un arquitecto: si el objetivo es vago, guía al agente a hacerte 2-3 preguntas antes de crear el plan; acepta un design (decisiones de stack/arquitectura) que queda como sección del plan; y al guardarlo devuelve planes similares que ya hiciste (para retomar, no duplicar), lecciones relevantes de la bóveda y sugerencias de calidad (DoD verificable por comando, tareas chicas). ¿Cómo comprueba el protocolo que el trabajo esté bien hecho, no solo "por encima"?How does the Protocol check the work is actually done, not just superficially?

La tool task_verify (v0.5.4+) recibe un verify_command (ej. npm test, npm run build) y lo ejecuta: el veredicto sale del exit code real, no de lo que el agente afirme. Si el agente dijo que pasó pero el comando falla, se registra el resultado real y se marca una discrepancia. Si no se pasa comando, la verificación queda etiquetada auto-reportado (no comprobada) y ale audit la delata. Así la verificación es evidencia real, no palabra.The task_verify tool (v0.5.4+) takes a verify_command (e.g. npm test, npm run build) and runs it: the verdict comes from the real exit code, not from what the agent claims. If the agent said it passed but the command fails, the real result is recorded and a discrepancy is flagged. Without a command the verification is tagged self-reported (unchecked) and ale audit calls it out. Verification is real evidence, not the agent's word.
